# 監査エンジン 入力仕様・判定根拠

対象：`tools/audit/shipping_audit.py`（宅配便請求監査・v0.2）

## 1. 出荷・請求CSV

UTF-8（BOM可）、1行目はヘッダ。運送会社ごとのCSVは、この標準形式に変換してから投入する（変換スクリプトは顧客の実データ受領後、形式ごとに作成）。

| 列名 | 必須 | 型 | 例 | 用途 |
|---|:---:|---|---|---|
| tracking_no | ○ | 文字列 | 1234-5678-9012 | 重複判定・根拠明細 |
| ship_date | ○ | YYYY-MM-DD | 2026-10-01 | 根拠明細 |
| carrier | ○ | 文字列 | 宅配便A | 運賃表の照合キー |
| service | ○ | 文字列 | 通常 | 運賃表の照合キー（`carrier:service`） |
| billed_size | ○ | 文字列 | 60 | 請求されたサイズ区分 |
| charged_yen | ○ | 数値（カンマ可） | 1,150 | 請求額（税の扱いは運賃表と揃える） |
| dest_pref | | 文字列 | 北海道 | 地域別単価の照合 |
| weight_kg | | 数値 | 1.2 | サイズ判定 |
| length_cm / width_cm / height_cm | | 数値 | 30 / 20 / 8 | サイズ判定・小型便判定 |

**含めてはいけない列**：お届け先の氏名・住所（都道府県以外）・電話番号・メールアドレス・注文者情報（`docs/legal/03_顧客データ取扱規程_初版.md` 第2条）。

## 2. 契約運賃表（JSON）

サンプル：`samples/ratecard_sample.json`（架空）。顧客ごとに `ratecard_{顧客ID}.json` を作成し、**原本と2回照合**する（リポジトリにはコミットしない。`.gitignore` 済み）。

```json
{
  "services": {
    "<carrier>:<service>": {
      "sizes": {
        "<区分>": {"max_sum_cm": 60, "max_kg": 2, "price": 720, "pref_prices": {"北海道": 1150}}
      }
    }
  },
  "small_packet": {"name": "...", "max_thickness_cm": 3, "max_long_cm": 34, "max_short_cm": 25, "max_kg": 1, "price": 330}
}
```

- `price`：基本の契約単価。`pref_prices` に都道府県があればそちらを優先
- `max_sum_cm` / `max_kg`：サイズ区分の上限。**運送会社の約款・顧客の契約書で必ず確認**（サンプルの値は一般的な区分を模した架空値）
- `small_packet`：小型配送便の条件と単価（省略可）

## 3. 入力チェック（黙って捨てない）

| 区分 | 条件 | 扱い |
|---|---|---|
| ERROR | 追跡番号・運送会社・サービス・サイズ・運賃のいずれかが空欄、運賃が数値でない／負 | その行は監査しない（重複判定にも使わない）。報告に行番号付きで表示 |
| WARN | 運賃表に該当サービス・サイズがない | 契約単価・サイズの照合をスキップ |
| WARN | 3辺寸法が一部のみ、寸法・重量が0以下または非数値 | サイズ判定・小型便判定をスキップ |
| WARN | 届け先都道府県が空欄 | 基本単価で照合 |

## 4. 判定ロジックと確度

| 区分 | 判定 | 「あるべき額」 | 確度 |
|---|---|---|---|
| 重複請求 | 同じ追跡番号の2回目以降 | 0円 | 確定（ただし運送会社の分割請求・再配達等の正当な理由がないか確認） |
| 契約単価超過 | 請求額 ＞ 運賃表の単価（サイズ×地域） | 契約単価 | 確定（運賃表の税区分・追加料金の扱いを確認） |
| サイズ区分の過大候補 | 3辺合計と重量の両方が収まる最小区分 ＜ 請求区分 | 最小区分の契約単価 | 要確認（実物・計測記録で確認。寸法が出荷時の計測値か商品マスタ値かで信頼度が変わる） |
| 小型便切替候補 | 厚さ・長辺・短辺・重量が小型便の条件内 | 小型便の単価 | 推定（補償額・ポスト投函・お届け日数など業務影響を顧客が判断） |

1行につき「サイズ区分の過大候補」と「小型便切替候補」は重複して計上しない（前者を優先）。
