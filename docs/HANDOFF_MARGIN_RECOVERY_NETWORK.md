## 1. 現在の方針（v0.3・2026-11-10 決定）
**小規模サロン向け「定額・半自動の固定費チェック」から始め、4週間で検証する。EC配送費の監査は Phase 2（成熟後）。**

| 項目 | 内容 |
|---|---|
| 対象 | 美容室・ネイル・エステ・まつげ（1〜5店舗） |
| 商品 | 固定費・集客費チェック 19,800円（税別）。見直し余地の上限×12か月が診断料を下回れば全額返金。月額2,980円の見直し通知は需要を確認してから作る |
| 仕組み | 5分の質問票 → 決定論的プログラムで判定 → 15分の説明。請求書などの書類は受け取らない。見直しはオーナー自身が行う |
| 当方がしないこと | 契約先との交渉・解約手続きの代行、税務相談・税務判断、乗換先からの紹介料の受け取り |
| 販路 | サロンオーナー同士の紹介、美容ディーラー・開業支援・予約/POS 事業者。**顧問税理士には紹介を頼まない**（税理士費用も見直し対象にするため利益相反） |
| 事業形態 | 個人事業（開業届は有料販売の直前でよい。合同会社化は当面不要） |
| 必要資金 | 約10〜25万円（4週間の検証は10万円以内） |

### 方針の経緯（なぜ今の形なのか）
1. **v0.1（2026-11-09）**：当初案「中小企業の経費全般を成功報酬で削減」を再評価。業界を100点満点で採点（EC年商1〜10億円 77点、多店舗サービス62点、美容室50点など）し、EC事業者の配送費監査（成功報酬＝削減額×12か月×25%）を選んだ。美容室は1店あたり報酬が約6万円で、月利益50万円に月12件の削減実現が必要なため却下した
2. **v0.2（2026-11-10、持ち主の経営判断報告書）**：個人事業で開始、弁護士レビュー15〜30万円、10社ヒアリング（データは受け取らない）、宅配便請求に限定、成功報酬を月次実績・後払い（最大12か月）に変更。結果、標準シナリオの月利益50万円到達が8か月目から16か月目に延び、必要資金が約60〜110万円で上限100万円を超えるおそれが出た
3. **v0.3（2026-11-10）**：持ち主の指摘（配送のノウハウがない、手作業が多い、資金・期間）を受けて方針転換。本当の問題は「成功報酬コンサルという形」だったと判断した。成功報酬型は実データ受領・手作業・反映確認・弁護士法72条リスクを伴う。そこで定額・半自動の診断に変え、対象をサロンにした
4. **追加判断（2026-11-10）**：会計アプリの自社開発はしない。freee・マネーフォワード・弥生が年1〜2万円台で提供済みで、税理士法52条のリスクもあるため。代わりに「税理士・記帳の費用」を診断の6番目の項目に加えた

### 持ち主の基本ルール
- 自分の作業は最小限にしたい。AIができることはAIがやる。コピペで済む形で指示がほしい
- 忖度しない。採算が合わなければ「やめる」と言う
- **顧客の実データ（店名・個別の金額・回答）を生成AI（Claude を含む）に入力しない。** 持ち主から受け取ってよいのは、ツールが作る「店名・個別金額なしの振り返り」だけ
- 送信・公開・契約・お金・削除・インストールは持ち主の承認が必要
- 法令：弁護士法72条（報酬目的の交渉・請求代行をしない）、税理士法52条（税務相談・申告書作成をしない）、特定電子メール法（営業メールは公表アドレス・拒否表示なしのみ、記録・即時停止）、景品表示法（実績のない削減額・平均削減率を表示しない、モデルケースは架空と明記）

## 2. 主力の実装：サロン固定費チェック（`tools/salon/`）

### 2-1. 判定エンジン `fixed_cost_check.py`（Python・決定論的）
- 実行：`python tools/salon/fixed_cost_check.py --input answers.json [--benchmarks tools/salon/benchmarks.json] [--price 19800] [--out-md report.md] [--out-json result.json]`
- 各項目に確度を付ける：**確定**（回答どおりなら確実に減らせる）／**推定**（条件変更が前提の見込み）／**要確認**（金額を出さず比較が必要）
- 金額は100円単位に四捨五入（`_r`、ブラウザ版と同じ丸め方）
- 6領域の判定ロジック：
  1. **決済（check_payment）**：キャッシュレス売上＝月商×キャッシュレス比率。見直し余地の下限＝キャッシュレス売上×max(現在料率−2.98%,0)、上限＝キャッシュレス売上×max(現在料率−2.48%,0)＋月額固定費。確度は推定。上限が0以下なら「見直し余地なし」のメモ
  2. **予約・POS・SaaS（check_saas）**：直近3か月使っていない有料ツールは**確定**（月額全額）。それ以外のツールについて、同じ機能（booking/pos/karte/messaging/payroll/accounting）を持つものが2つ以上あり、うち1つ以上が有料なら**推定**（0〜有料の最安額）。未使用の有料ツールは重複判定から除く（二重計上防止）
  3. **通信（check_telecom）**：使っていない回線は**確定**（月額全額）。最後の見直しから3年以上で使用中の回線があれば**要確認**（金額0）
  4. **電気（check_electricity）**：実質単価＝電気代÷kWh を示すだけ（**要確認**・金額0。燃料費調整・支援策で単価が変動するため削減額を出さない）。kWh が無ければメモ
  5. **集客（check_acquisition）**：媒体ごとに費用＝掲載費＋予約手数料等。新規0人なら**要確認**（0〜費用）。新規1人あたり獲得コスト＞新規客の1年目の粗利（客単価×1年目の来店回数×粗利率）なら**推定**（0〜(獲得コスト−粗利)×新規数）。以内ならメモ
  6. **税理士・記帳（check_accounting）**：年商帯で「申告のみ」の相場を選ぶ（1,000万円未満 7〜15万円、3,000万円未満 10〜20万円、それ以上は相場なしで**要確認**・金額0）。記帳を任せていない契約で相場上限を超えれば**要確認**（金額0）、範囲内ならメモ。記帳込みの契約なら、代替＝会計アプリ年10,800〜23,760円＋申告のみの相場。年額が代替の下限以下ならメモ。超えていれば**推定**で、下限＝max(年額−代替上限,0)÷12、上限＝(年額−代替下限)÷12。従業員がいれば給与計算・年末調整の注意を加える。税務相談はしない旨を必ず添える
- 出力（Markdown）：見直し余地の月額・年額レンジ、「確定」の合計、返金保証の判定（上限×12＜診断料なら返金対象と明記）、項目表（領域・項目・確度・月の目安・根拠・お客様が行うこと・注意）、問題なし/判定不可の項目、比較基準の出典
- 出力（JSON）：salon、monthly_low、monthly_high、items、notes

### 2-3. ブラウザ版 `check.html`（オーナーと一緒に入力し、その場で結果を出す道具）
- HTMLファイル1つ。**インターネット接続なしで動き、外部通信は一切ない**（フォントも読み込まない。ブラウザで検証済み：外部リクエスト0件・エラー0件・スマホ幅で横スクロールなし）
- 入力フォーム7節：1 基本（店名・月商・診断料）、2 決済（キャッシュレス比率・カード手数料率・月額固定費）、3 ツール（名前・月額・機能のチェック・直近3か月使ったか。行の追加・削除可）、4 回線（名前・月額・使用中か。行の追加・削除可。見直しからの年数）、5 電気（プラン名・電気代・kWh）、6 集客媒体（名前・掲載費・予約手数料等・新規数。行の追加・削除可。客単価・1年目の来店回数・粗利率）、7 税理士・記帳（年間支払い・記帳も任せているか・従業員の有無）
- 空欄の項目は判定しない。集客の判定に必要な3項目が欠けていれば注意を表示
- ボタン：結果を出す／結果を印刷・PDF保存（印刷用の見た目）／回答を保存（JSON をダウンロード）／回答を読み込む（JSON）／架空サンプルを入れる
- 判定ロジックは `<script id="logic">`、比較基準は `<script id="benchmarks">` に埋め込み。**Python 版と同じ判定・同じ基準であることをテストで保証**している（基準を更新したら両方を同じ内容にする）
- **振り返り機能**（オーナーとの話が終わったら記入）：お店の種類・店舗数・所要時間（分）・価格の反応（払わない／9,800円なら／19,800円なら／それ以上でも）・紹介してもらえそうな人数・一番時間がかかった項目・分かりにくかった質問（1〜7のチェック）・「やってみる」と言った項目（結果の領域から自動生成）・一番困っていること・メモ。「Claude に送る振り返りをコピー」で、**店名・個別の金額を含まない要約文**（年商帯、合計レンジは1,000円単位、領域ごとの確度、返金対象か、各回答）を作る。クリップボードに入らない環境では選択して手動コピー
