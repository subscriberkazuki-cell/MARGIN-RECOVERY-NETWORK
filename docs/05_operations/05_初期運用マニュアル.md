# 初期運用マニュアル

> v0.2（2026-11-10）：**本マニュアルの第3〜4節（顧客データの受領・監査・請求）は、弁護士レビュー完了・データ取扱規程の施行・（必要なら）合同会社化の後に運用を開始する。** それまではヒアリング（`01_顧客ヒアリングシート.md`）のみ。

対象：創業者（1〜2名）。Phase 1〜3 の手動・半自動運用。

## 1. 日次ルーティン（約60分）

| 時刻 | 作業 | ツール |
|---|---|---|
| 朝 | 返信の確認・分類（Agent3の分類案を確認） | メール、Cowork |
| 朝 | **配信停止依頼を即日処理**（除外リストに追加） | 営業スプレッドシート |
| 午前 | 送信予定の文面を承認・送信（1日20〜30件上限） | メール |
| 午後 | 受領した顧客データの処理（下記 3.） | 共有ドライブ、`tools/audit` |
| 夕 | 案件表の更新 | スプレッドシート |

## 2. 週次ルーティン

- 月：Agent2 が翌週の見込み客を抽出 → 送信可否の抜き取り確認（10件）
- 水：パートナー対応
- 金：KPI定例（`docs/06_plan/01_90日実行計画.md` 末尾）

## 3. 顧客データの受領と監査（手順）

1. 共有フォルダに顧客がファイルを置いたら、**まず個人情報列の有無を確認**。氏名・住所・電話があれば、その列を削除したコピーを作成し、原本は即削除。顧客に削除済みである旨を連絡
2. 運送会社のCSV形式を標準形式（`tools/audit/INPUT_SPEC.md`）に変換
3. 契約料金表を `ratecard_{顧客ID}.json` に転記（サンプル：`tools/audit/samples/ratecard_sample.json`）。**転記後に別の人またはもう一度、原本と照合**
4. 実行：
   ```bash
   python3 tools/audit/shipping_audit.py --shipments <CSV> --ratecard <JSON> --months 1 --client "<会社名>" --out-md result.md --out-json result.json
   ```
5. 結果を確認：「確定」の明細を5件抜き取り、原本の請求と一致するか確認
6. レポート作成（`docs/05_operations/04_監査レポートテンプレート.md`）。**顧客の実データ・行単位の結果・顧客名・取引先名・単価を Claude Cowork／Claude Code／外部AIに入力しない**。文章の雛形づくりにAIを使う場合は架空値か集計値のみ。数値は監査エンジンのJSONから人間が転記・照合
7. 顧客へ送付（承認後）

**禁止事項**：顧客データをリポジトリ（Git）にコミットしない。顧客データを私用アカウント・私用クラウドに保存しない。初期段階では顧客データを外部の生成AIサービス（Claude Cowork・Claude Code を含む）に入力しない（`docs/legal/03_顧客データ取扱規程_初版.md` 第6条）。

## 4. 効果確認と請求（弁護士レビュー後に運用開始）

1. 毎月、当月の宅配便請求明細を受領
2. 区分別（サイズ・地域・サービスが同一条件）に「当月の実出荷数 × 当月に実際に適用された1個あたり削減額」を算定（算定シートに根拠を残す）
3. 算定表を顧客に送付し、確認期間（例：7日）内の異議を受け付ける。合意できない部分は請求しない
4. 請求書発行（当月削減額の25%）。反映月から最大12か月で終了

## 5. トラブル対応

| 事象 | 対応 |
|---|---|
| 顧客が算定額に異議 | 根拠明細を提示。合意できない部分は請求しない（関係維持を優先） |
| 運送会社・3PLが過請求を否定 | 当社は関与を終了。顧客に契約書の該当条項を示し、必要なら弁護士相談を勧める |
| 誤った指摘をしてしまった | 直ちに訂正版を発行し謝罪。原因（料金表の転記ミス等）を記録し、チェック手順を追加 |
| 個人情報を含むデータを受領 | 即時マスキング・原本削除、顧客へ報告、記録 |
| 営業メールへの苦情 | 謝罪・即日除外。取得元・判定記録を確認し、同種の宛先を一括見直し |

## 6. 品質基準

- 「確定」と表示した指摘の誤り率：0%（1件でも誤りがあれば手順を見直す）
- 無料診断の人手時間：15分以内
- 診断申込から結果説明まで：7営業日以内
