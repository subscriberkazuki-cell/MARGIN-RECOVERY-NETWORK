# WORKFLOWS（業務フロー）

すべて「指示 → 分解 → 専門エージェント → 検証 → 独立レビュー → 修正（2回まで） → 成果物 → 記憶保存」。人間の承認が必要な工程では止まる。

## A. 調査・分析 — `/research テーマ`
1. 問いを3〜7個に分解（期間・地域・定義を決める）
2. AI_Hub の過去の調査を確認して再利用
3. research-analyst が一次情報を中心に収集（独立した問いが多いときだけ2体）
4. 重要な数値を出典で再確認
5. 意思決定に使うなら quality-reviewer が反対の証拠を探す
6. 結論・事実（出典つき）・推測・リスク・未確認事項でまとめる → `03_Research/` に保存

## B. 株式分析 — `/stock-a NVDA FY2027Q3`、続けて `/stock-b NVDA`
1. 企業・決算期・発表日を確定（一次資料）
2. 財務（売上・営業利益・EPS・営業CF・FCF）→ 稼ぐ事業 → 成長ドライバー TOP1〜2（セグメント寄与を定量化）→ 中国依存・供給制約 → KPI と予想の差 → バリュエーション → ブル/ベア → Core Definition
3. quality-reviewer が期間の取り違え・GAAP/非GAAP・出典の期間ずれを審査
4. `/stock-b` で TOP1・TOP2 ごとに日米競合を100点満点で採点（60点未満は除外、最大3社）
5. `01_Projects/Investment/{ティッカー}/` に保存

## C. 新規事業 — `/business-review アイデア`
1. 持ち主の制約と過去の却下案を確認 → 市場・競合・世界の類似モデルを調査
2. ビジネスモデル（価格・原価・販路・作業時間）→ 3シナリオの採算をプログラムで計算
3. quality-reviewer（Red Team）が失敗シナリオと前提の甘さを洗い出す → 作り直し（2回まで）
4. 「進める／条件付き／やめる」と、最初の検証（合格・撤退基準）→ DECISIONS に保存

## D. YouTube → 記事・SNS — `/content-production https://youtu.be/...`
1. 字幕・文字起こしを取得。**取れなければ、その事実と理由を報告して止まり**、文字起こしの貼り付けを依頼（字幕取得ツールの導入は承認が必要）
2. 要点抽出（タイムスタンプ付き）→ 記事構成 → 本文 → SNS投稿案 → 画像の指示
3. quality-reviewer が事実・日本語・誤解を招く表現・著作権を審査
4. `04_Outputs/` に保存。公開・投稿は人間

## E. Webサービス開発 — `/project-build 内容`
1. 既存コード・テスト方法・`git status` を確認、過去の決定を AI_Hub から読む
2. 受け入れ条件 → 設計・計画（大きな変更は計画を見せてから）→ 作業ブランチ
3. 実装 → テスト・型チェック・ビルドを実際に実行
4. technical-qa が独立検査 → 修正（2回まで）
5. 報告。push・デプロイは承認後

## 記憶 — `/remember 内容`（または「覚えて」）
重複確認 → 決定/仮説の区別 → 出典 → 変更履歴 → 適切な保存先 → MEMORY_INDEX に1行。秘密情報は保存しない。

## MCP・外部ツールを追加するとき
1. 本当に必要か（ファイル操作や既存スキルで足りないか）
2. 提供元・メンテナンス状況・必要な権限・認証方式・データの送信先・費用を確認して持ち主に提示
3. 承認後に `claude mcp add`（読み取りだけで足りるなら読み取り権限のみ）。秘密情報は環境変数で渡し、ファイルに書かない
4. SYSTEM_ARCHITECTURE と CHANGELOG を更新
